# xray_client (xdiag) — инструкции для агентов

Приложение диагностики подключений VLESS + REALITY + XHTTP на Windows 11 для установки из
`grokki91/xray`. Проект — `docs/architecture.md`, состояние — `docs/implementation.md`.
Отвечать на русском.

## Публичный репозиторий: данные установки — никогда

В код, комментарии, тесты, фикстуры, README, коммиты и PR не попадает ничего, что
идентифицирует установку владельца:

- IP сервера, хостер, домены владельца, SNI маски установки;
- UUID, ключи и shortId REALITY, путь XHTTP, URL подписки;
- фактические порты установки, если они не 443;
- вывод программ с ПК или сервера как есть (логи, `doctor.json`, дампы, скриншоты с адресами).

Примеры — `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` (RFC 5737), `example.com`;
UUID в тестах — `00000000-0000-4000-8000-…`; ключи — сгенерированные для теста (как в
`internal/sim`). `go test ./internal/repocheck/` проверяет рабочее дерево: IP вне
документационных и частных сетей и UUID — провал. Убрать, а не обходить.

## Конфиденциальность в коде

- Всё, что показывается или сохраняется вне DPAPI, проходит `internal/redact`; новый вид
  секрета — регистрировать в редакторе (`Profile.Register`, `redact.Add`).
- Секреты на диске — только `store.SaveVault` / `SaveSession` (DPAPI). Открытым текстом —
  только `settings.json`, индекс истории и бюджет (без адресов).
- Секреты не передаются в командной строке процессов (видна всем): stdin, файл в каталоге
  данных или переменная окружения.
- В окне — только `textContent` (строки логов недоверенные).

## Сеть

- Бюджет приложения C: ≤ 3 TLS к серверу за 60 с, ≤ 6 TCP за 5 минут; любая новая проба к
  серверу — через `netprobe.Budget`, эталонное ядро — только через `refcore` (его сокеты идут
  через диалер приложения).
- Приложение ничего не меняет в системе: маршруты, DNS, файрвол, службы, профили клиентов.
- «Таймаут ≠ блокировка»: гипотеза `path.*` — только с `gate: N1.ok=true` и `alternative`;
  «подтверждено» — только окном сервера (S3) или другой сетью (P5). Загрузчик правил это
  проверяет.

## Правила и факты

- Причины, проверки и тексты — в `rules/*.yaml`, не в Go. Новый код — в `taxonomy.yaml`,
  гипотеза — в `hypotheses/`, сценарий — в `internal/rules/rules_test.go`.
- Версии клиентов, ядер и правила сервера — `rules/compat.yaml`; источник —
  `grokki91/xray` `.claude/skills/xray-dpi/references/landscape.md`. Правка факта — с датой
  и источником, в обоих репозиториях.
- Формат вывода `xm doctor`/`xm health` — по `ui/doctor.py`/`ui/health.py` сервера;
  изменение контракта — `schema.major` и тест в `internal/bridge`.

## Проверка перед коммитом

```bash
gofmt -l cmd internal rules      # пусто
go vet ./... && GOOS=windows go vet -tags desktop,production ./...
go test ./...                    # сетевой симулятор: REALITY-сервер Xray-core на петле
```

Тест доказывает эффект правки: с откаченной правкой он падает. Поведение на живой Windows и
живом сервере тестами не доказывается — так и писать в PR («не проверено на Windows/сервере»).
