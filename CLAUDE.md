## Claude Code

- Скил `diagnostics` — до первого ответа в любой задаче о том, почему VPN не подключается или
  работает не так и что должен сказать xdiag: скрин, отчёт, экспорт сеанса, новая проверка,
  улика или правило. `pr-description` — при каждом создании и обновлении PR.
  `ml-system-design-review` — ревью архитектуры и системного дизайна; `lossless-doc-compress` —
  сжать текст без потерь; оба сначала грузят свой `references/xdiag.md`.
- `.claude/rules/*.md` подгружаются сами, когда читаешь или правишь файлы из их `paths`.
- Тело PR — без «Generated with Claude Code» и без ссылки на сессию: правило владельца
  (`pr-description`) важнее умолчаний среды. В коммитах подпись (`Co-Authored-By`,
  `Claude-Session`) остаётся.
- Хук `.claude/hooks/commit-guard.sh` не пускает `git commit`/`git push`, пока не зелёный
  `go test ./internal/repocheck/` (дерево и текст команды); без `jq`/`go` молча пропускает.
- Большие файлы — по разделам (`grep -n`, `offset`/`limit`): `docs/architecture.md` ≈ 830 строк,
  `internal/engine/phase_net.go` ≈ 750.

# Compact instructions

При сжатии сохранять: требования задачи, принятые решения и почему, изменённые файлы, имена
сценариев с ожидаемыми кодами и уровнями, открытые вопросы и недостающие данные. Не сохранять
содержимое прочитанных файлов, отчётов, логов и сырые выводы команд — их можно перечитать.
