# xdiag

Приложение для Windows 11, которое объясняет, **почему VPN-клиент не подключается**
(например, пишет «таймаут»). Подходит для серверов **VLESS + REALITY** с транспортом
**XHTTP** или **TCP** (в том числе с Vision) и клиентов **Hiddify** и **v2rayN**. Нажимаете
одну кнопку и получаете причину, улики и что делать дальше.

## Стек

- **Go**: ядро диагностики и консольная версия
- **Wails**: окно приложения (HTML, CSS, JavaScript)
- **Xray-core**: встроенное эталонное ядро для контрольного подключения
- **YAML**: правила диагностики (причины, проверки, тексты)
- **SQLite**: чтение баз профилей клиентов

Подробности: [docs/architecture.md](docs/architecture.md) и
[docs/implementation.md](docs/implementation.md).

## Что и как проверяется

1. **Клиент.** Читает файлы Hiddify или v2rayN: версию, ядро, профили, логи. Смотрит,
   запущен ли процесс, слушает ли локальный прокси, поднят ли TUN.
2. **Windows.** Один PowerShell-скрипт, который только читает: сетевые адаптеры и другие VPN,
   маршрут до сервера, DNS, брандмауэр, антивирус, системный прокси, часы, IPv6, MTU.
3. **Сеть.** Открываются ли напрямую, мимо VPN, несколько обычных незаблокированных сайтов,
   российских и зарубежных. Так видно, есть ли интернет вообще и не похоже ли на белый
   список. Сравнивает ответы DNS по разным каналам, чтобы заметить подмену. Это признаки, а
   не доказательство: такую же картину может дать и другое (фильтр на роутере, корпоративный
   прокси, VPN-клиент, который не удалось обойти). Белый список подтверждается повтором из
   другой сети.
4. **Сервер снаружи.** Открыт ли порт, отвечает ли TLS, затем одна настоящая попытка
   подключиться с вашим профилем через встроенное ядро Xray. По этой попытке видно, где
   проблема: в сервере и пути до него или в самом клиенте. Если тоннель поднялся, то же ядро
   проверяет, что открывается за ним.
5. **По желанию:** данные с сервера (см. [ниже](#сервер-необязательно)) и захват ClientHello
   клиента (нужны права администратора).

Приложение ничего не меняет: маршруты, DNS, брандмауэр, службы и профили клиентов остаются
как были. Чтобы диагностика сама не выглядела как атака, к серверу уходит не больше 3
TLS-соединений в минуту. Счётчик виден в окне.

## Установка

1. Скачайте готовую сборку на вкладке **Actions** (артефакт `xdiag-windows-amd64`) или в
   **Releases** репозитория:
   - `xdiag-ui.exe` — приложение с окном (для большинства пользователей);
   - `xdiag.exe` — версия для терминала.
2. При первом запуске Windows SmartScreen может предупредить, что файл не подписан. Нажмите
   **«Подробнее» → «Выполнить в любом случае»**.

Как собрать самому (нужны Go 1.26+ и git): выполните в PowerShell в папке проекта
`.\build.ps1`, готовые файлы появятся в `dist\`.

## Как пользоваться

1. Убедитесь, что профиль сервера добавлен в Hiddify или v2rayN. Подключаться не нужно:
   приложение возьмёт профиль из клиента и само сделает контрольную попытку. Если клиента
   нет, вставьте ссылку `vless://` на вкладке **«Настройки»**.

   Какой профиль проверяется: в v2rayN — тот, с которым последний раз запускалось ядро,
   иначе выбранный в списке; в Hiddify — первый сервер VLESS + REALITY в активном профиле.
   Профиль из настроек берётся, только если в клиенте подходящего нет.
2. Запустите `xdiag-ui.exe`.
3. На вкладке **«Диагностика»** нажмите **«Диагностировать»** и дождитесь конца проверок.
4. Прочитайте результат:
   - **Причина** и насколько она надёжна;
   - **Улики**: на чём основан вывод;
   - **Что делать**: конкретные шаги;
   - **Исключено**: что точно в порядке.
5. Полные результаты можно сохранить:
   - **«Скопировать отчёт (без адресов)»** — текст: вывод, все проверки сеанса и найденные
     строки логов клиента;
   - **«Экспорт JSON…»** — весь сеанс со всеми собранными фактами в файл.

   Адреса, ключи, UUID и пути в обоих случаях заменены метками (`[server]`, `[sni]` и т. п.).
   Адрес сервера попадает в экспорт, только если включить это в настройках.

Дополнительные опции на вкладке «Диагностика»:

- **Клиент**: какой клиент проверять, если установлено несколько;
- **«Я в другой сети»**: запустите ещё раз из другой сети (например, с мобильного
  интернета), и приложение сравнит результаты;
- **«Углублённо: захват (UAC)»**: проверяет, что клиент на самом деле отправляет серверу.
  Windows попросит права администратора;
- **«Вставить логи клиента»**: если приложение не нашло логи само;
- **«Мост к серверу (SSH)»** и **«Импорт doctor.json / health.json»**: см.
  [«Сервер»](#сервер-необязательно).

### Вкладки

| Вкладка | Для чего |
|---|---|
| Диагностика | запуск проверки и результат |
| Подробно | все проверки последнего сеанса и строки логов |
| История | прошлые проверки, к ним можно вернуться |
| Настройки | профиль, папки клиентов и параметры проверки |
| Данные | где хранятся данные, как их посмотреть; команды для ручной работы с сервером |

### Настройки

**Обязательных полей нет.** Если клиент установлен и в нём есть профиль, всё работает со
значениями по умолчанию. Профиль нужен, только когда приложение не нашло его в клиенте.

| Поле | За что отвечает |
|---|---|
| Профиль `vless://` | профиль для проверки, если клиента нет или в нём нет профиля. Если клиент есть, профили сверяются |
| SSH-алиас сервера | имя `Host` из `~/.ssh/config` для моста к серверу (вход по ключу, без пароля). Нужен только для моста |
| Папка v2rayN | если v2rayN портативный и не нашёлся сам |
| Папка данных Hiddify | если Hiddify установлен не в стандартное место |
| Клиент по умолчанию | какой клиент проверять: определять сам, Hiddify или v2rayN |
| Хранить историю, дней | через сколько дней удалять старые сеансы (по умолчанию 30) |
| Окно xm doctor, с | сколько секунд сервер слушает попытки подключения при работе через мост (по умолчанию 60) |
| Эталонная проба Xray-core | контрольное подключение встроенным ядром (по умолчанию включено). Без него вывод менее точный |
| Мост к серверу по умолчанию | включать мост при каждой проверке |
| В экспорт включать адрес сервера | добавить адрес сервера в экспорт JSON (по умолчанию выключено) |

После изменений нажмите **«Сохранить»**.

### Терминал

```powershell
xdiag run                    # диагностика
xdiag run --client v2rayn    # проверить конкретный клиент
xdiag history                # история проверок
```

## Сервер (необязательно)

xdiag работает **самостоятельно** с любым сервером VLESS + REALITY: 3x-ui, чистый Xray или
другая установка. Всё описанное выше доступно без каких-либо действий на сервере.

В приложении также встречаются команды `xm` (`xm doctor`, `xm bridge`, `xm uri` и т. п.):
в советах «Что делать», во вкладке «Данные», в опциях моста и импорта. Это команды
управления сервером из проекта [grokki91/xray](https://github.com/grokki91/xray). Если сервер
поставлен оттуда, xdiag дополнительно видит, что происходит на сервере в момент
подключения, и вывод становится точнее:

- **вручную:** запустите на сервере команды из вкладки «Данные», скопируйте полученные файлы
  на ПК и нажмите «Импорт doctor.json / health.json»;
- **через мост:** укажите SSH-алиас в настройках и включите «Мост к серверу (SSH)». Нужна
  поддержка `xm bridge` на сервере.

Для другого сервера эти опции и советы с `xm` просто не применяются.

## Конфиденциальность

- Профиль и настройки хранятся только на этом компьютере, зашифрованные Windows DPAPI для
  вашей учётной записи.
- В окне, отчёте и экспорте вместо адресов, ключей и идентификаторов стоят метки.
- Приложение ничего не отправляет разработчику.
