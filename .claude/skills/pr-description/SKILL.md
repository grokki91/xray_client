# Описание pull request

Пиши минимум. Только что добавлено/изменено, тезисно, на русском.

## Формат

```
- <что добавлено>
- <что изменено>
```

- 2–6 пунктов, каждый — одна короткая строка без пояснений «зачем» и «как».
- Заголовок PR — одна короткая фраза.
- Если поведение не проверено на живой Windows/сервере — последний пункт
  `- не проверено на Windows/сервере`.
- PR меняет приложение — в нём есть файл `changes/<ветка>.md` (см. AGENTS.md, «Версия
  приложения»); первый пункт описания — уровень и номер: `- версия: patch (1.4.3 на момент PR)`
  (номер — `go run ./cmd/version`; если раньше сольют другой PR, при слиянии станет больше).

## Не писать

- разделы «Что было не так», «Проверка», «Отступление от AGENTS.md», «Что сделано» и любые
  другие заголовки;
- таблицы, предысторию, причины, списки тестов и команд;
- подпись вроде «Generated by Claude Code», ссылки на сессию, разделитель `---` в конце.

## Ответ в чате после PR

Сначала — PowerShell-блок проверки на живом клиенте, всегда ровно в таком виде (вместо `<N>` —
номер PR; без PR — имя ветки):

```powershell
iwr https://raw.githubusercontent.com/grokki91/xray_client/main/try-pr.ps1 -UseBasicParsing -OutFile $env:TEMP\try-pr.ps1; powershell -ep Bypass -f $env:TEMP\try-pr.ps1 <N>
```

- Скрипт берётся из `main` по сети и кладётся в `%TEMP%` — от локальной копии проекта команда
  не зависит и запускается из любой папки. Сборку ветки скрипт сам кладёт в
  `%TEMP%\xdiag-<коммит>` и запускает `xdiag-ui.exe` оттуда.
- Не предлагать `.\try-pr.ps1`, `cd` в папку проекта или `dist\`: локальная копия бывает
  старше `main`, и файла там нет.
- Если PR меняет сам `try-pr.ps1` — заменить в URL `main` на имя ветки PR.

Затем — раздел **Ожидаемый результат**:
критерии приёмки, по которым видно, что всё ок.

```
**Ожидаемый результат**
- [UI] рядом с кнопкой «Проверить» — зелёная галочка
- [Терминал] `status 200`, без ошибок
```

- Если PR меняет приложение — пункт про номер: `- [UI] «О программе»: версия 1.4.3`.
- 2–5 пунктов, каждый — одна строка: где смотреть (`[UI]`, `[Терминал]`, `[Лог]`, `[Файл]`)
  и что конкретно должно быть видно (текст, цвет, код, строка лога).
- Только наблюдаемое; без пояснений «почему».
- Если что-то должно исчезнуть или не появиться — тоже пункт («[UI] ошибки X больше нет»).
- В описание PR этот раздел не попадает — только в ответ.

Данные установки (IP, домены, UUID, ключи и т. п.) в PR по-прежнему запрещены — см. AGENTS.md.
