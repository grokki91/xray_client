# Ревью системного дизайна xdiag

xdiag — не ML, но по устройству классификатор: улики → гипотезы → код причины с ординальным
уровнем уверенности (проект §7). Поэтому рамка Кравченко и Бабушкина применима почти целиком:
у «модели» есть разметка (сценарии), базовые линии (эталоны), цена ошибок (ложная «блокировка»),
валидация на данных из прода (повтор истории). Этот файл задаёт, чем в xdiag является каждое
измерение, и перекрывает остальной скил там, где они расходятся.

## Классификация (обязательный первый шаг)

- Режим — **doc and repo**: проект `docs/architecture.md` (v0.1, не обновляется), состояние и
  отличия — `docs/implementation.md`, правда — код и `rules/*.yaml` (AGENTS.md, «Где правда»).
  Formal Doc Gate не применять: документы есть.
- Стадия — **production / maintenance** (этапы 1–3 сделаны, `implementation.md`, «Сделано»).
  Мониторинг, релиз и сопровождение оцениваются, а не `n/a (stage)`.
- Задача — диагностический классификатор причин; пользователь — владелец VPN на Windows 11;
  решение, которое он принимает по выводу, — «минимальное действие».
- Худшая ошибка — уверенно названная неверная причина, после которой человек ломает рабочий
  профиль или сервер; затем — утечка данных установки; затем — проба, ухудшившая соединение
  (лишние TLS → заморозка по отпечатку).
- Modern-AI-строка — `n/a`: в приложении нет LLM. Ставить её только при ревью самого
  агентного контура (`.claude/`), и тогда это отдельный отчёт.

## Что считать находкой

- Расхождение проекта и кода — находка, только если его нет в `implementation.md`, «Отличия от
  проекта». Записанное отличие — решение, его оценивают по существу.
- Код и `rules/*.yaml` расходятся с `implementation.md` — находка (документ состояния лжёт).
- Правило или скил `.claude/` говорит неправду о коде — находка (AGENTS.md, «Инструкции
  меняются вместе с кодом»).
- Гипотеза `path.*` без `gate: N1.ok=true`, без `alternative` или с «подтверждено» не от S3/P5;
  проба к серверу мимо `netprobe.Budget`; секрет мимо `redact`; секрет в командной строке —
  critical.
- Поведение на живой Windows и живом сервере тестами не доказано — это неопределённость, не
  находка; так и писать.
- Исправление в «Prioritized fix plan» проходит фильтр приоритетов AGENTS.md: правка, не
  улучшающая диагностику, стабильность, расширяемость или сопровождение, не предлагается.
  Не предлагать ML-инструментарий (feature store, A/B, дрейф моделей) там, где его роль уже
  выполняет механизм из таблицы выше.

## Вывод

- Отчёт на русском; строка атрибуции скоркарда — как в `output-templates.md`, без изменений.
  Названия измерений в гредкарте — как в `rubrics.md` (английские), пояснения — по-русски;
  фразу «Valerii and Arseny» — по-русски («Валерий и Арсений…»), только вместе.
- Скоркард сохранять не в корень репозитория, а в каталог scratchpad сессии (если его нет —
  во временный каталог вне дерева) и назвать полный путь; в репозиторий, PR и коммиты он не
  попадает.
- Ссылки на улики — `путь:строка`. Данные установки (IP, домены, UUID, ключи, порты не 443,
  сырые логи) не цитировать — AGENTS.md, «Публичный репозиторий».
- Ревью ничего не правит. Правки по итогам — отдельной задачей, по `diagnostics` и AGENTS.md.
- Факт, вероятная причина и непроверенная гипотеза — раздельно.
